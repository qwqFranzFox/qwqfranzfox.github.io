Rust相关设计

Slotmap

这里使用Slotmap当作一种图状结构的存储方式，保存key代替指针，防止unsafe满天飞。 可能后续会把Slotmap替换成自己写的内存池之类。但是写指针，还是太神秘了，首先是不符合Rust的特色。真写的话还得再加一层wrapper，包装掉unsafe。而且同时这样垃圾回收会比较难做，正常的Mark-Sweep用slotmap可以简单的写成“标记收集可达元素，然后在slotmap里面purge未被mark的元素”

运行环境和逻辑的分离实现

我将其称为一种“语言虚拟机”。也就是你可以写出这种代码：

let lisp_a = Lisp::new();
let lisp_b = Lisp::new();
// run some code in lisp_a...
// run some code in lisp_b...
// and they are isolated

这个背后的实现动力是初版使用全局ENV（环境指针）的不便与混淆。通过把slotmap和env err tru等常量的Key打包放在一个结构体里面，然后所有访问其他元素的核心函数都做成LispContext的成员函数，而不是Data的函数——之前是这样的，所以必须依赖外部的ENV和allocator。然后再把这个LispContext放在Lisp里面，和Tokenizer Parser都做好接口交互，这就是一个完整的闭环。

Debug打印对象

我们做了Key和LispContext，也就是其实际数据的Allocator的分离。那么我们怎么做Debug打印呢？我想到了defmt的Display2Format，其实就是临时构造一个用Display实现Format的对象。同样的思路我和AI聊过之后他给了我这样一段代码：

use std::fmt;
use slotmap::SlotMap;
// 假设已有 LispKey 和 LispVal 定义
struct LispValDebug<'a> {
    key: LispKey,
    mem: &'a SlotMap<LispKey, LispVal>,
}
impl fmt::Debug for LispValDebug<'_> {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        let mut seen = std::collections::HashSet::new();
        self.fmt_inner(self.key, f, &mut seen)
    }
}

对，通过把数据的所有权也就是slotmap（在实际代码中是LispContext）和Key打包，就能在这个对象中获取实际的值并打印了。至于这里的seen标记我暂时没有加上，目前不考虑递归数据结构。

迭代器

所有的Tokenizer是实现为迭代器的，同时Parser有对应的ParserIter，方便处理多行代码的情况。但是ParserIter这一整个链条目前还没有达到我想要的程度，也就是无缝处理多行、带注释的代码。不过这一部分我基本上没看懂原项目是怎么写的，所以直接自己写了。

硬件相关

Primitive blink

本来这个Prims::Blink是用来实现控制LED定时善良的，而且本来理论上还有一个delay（但后来想了想和好像和延迟求值的原语撞名字了），后面为什么一起取消了，因为实际上发现做外设共享很难，需要一口气分发到Prim运行的里面，现在有了LispContext之后会好很多，但是又要处理多个Lisp分别使用同一个LED的问题了。不过现在剥离了全局环境之后感觉会好做很多。

[RP235x特有] 双核绑核通信

来了，最神秘的部分。双核的通信一开始是用了核间 FIFO 队列通信，然后用一个简单的共享的环形缓冲区做队列。后来发现这个版本拥有严重的锁占据问题，具体应该是USB串口轮询核的循环周期小很多，于是就卡死了Eval核对队列锁的获取。后面用了heapless::spsc的SPSC队列之后还是差不多，最后还是调试的时候加的LED闪亮的那一下延迟解决了问题，太神奇了，到现在我还没有明白具体是什么原因。
